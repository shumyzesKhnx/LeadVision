# Technical decisions

## Module 05 — Leads, corrections and CSV

Implemented public website syntax/identity validation without DNS requests or fetching. Shared companies identify normalized domains only; campaign leads have independent fields/provenance. New leads start New, with null scores and Needs review priority. Case/www/scheme/path/query/port variants collide within a campaign; arbitrary subdomains remain separate. Name-only matches warn without merging. Corrections append scalar JSON fact revisions, retain superseded values, and distinguish edit revision from analytical input revision. Deletion requires If-Match/explicit confirmation, cascades facts/lead activities, keeps campaign audit history, and removes only unused company identities. Active-job/artifact/result integration is deferred to modules 06/07/11/13; no such records are fabricated.

Added python-multipart 0.0.32 for Swagger file uploads while preserving existing dependency versions. CSV request-body and file caps are enforced separately; UTF-8/BOM, headers, quoting and the 100-record limit are validated before writing. Each valid row commits independently with campaign preflight rechecked. Systemic failures keep a complete bounded report under error.import_report, retaining accepted rows and marking unfinished rows not_processed. Template/demo CSVs use fictional data. Verified 215 tests and live health/docs/OpenAPI/leads/template; all prior domain/activity/maintenance records match their pre-upgrade fingerprints. A SQLite snapshot was saved in local ignored cache before migration 005. No demo leads, commits or pushes were created automatically.

## Module 04 — Campaigns

Implemented campaign create/read/edit/archive/reactivation in the existing API/service/repository layout. Campaigns select an active same-workspace ICP; database composite ownership constraints and RESTRICT references preserve history. Reads expose the selected ICP's current version without rewriting campaign revision or older configurations. The reusable work guard blocks archived campaigns and unavailable ICPs, and the currentness helper compares saved ICP/version identities. Actual lead/job/score/dashboard integration stays in its owning modules. ICP analytical/archive edits now report real linked campaign counts, including archived campaigns; affected results remain zero. Activity and cleanup tables are rebuilt together in migration 004 so adding the campaign foreign key cannot clear old cleanup links. Verified 145 tests and live routes with exact preservation of all preexisting domain/activity/maintenance records. A pre-upgrade SQLite snapshot is in ignored local cache. No example campaign, commit or push was created automatically.

## Module 03 — Ideal customer profiles

Implemented customer-profile CRUD/archive and immutable analytical configurations in migration 003. Entity revisions track all edits; configuration versions track analytical changes only. A composite foreign key ensures the current version belongs to its profile, and triggers prevent historical version updates/deletes. Configuration JSON, rule version and hashes are inserted with the pointer/activity update in one short transaction. Nested PATCH objects replace the complete object and use defaults for omitted members. Industry synonyms and country/region presets are explicit; free-text preferences never become exclusions. Known/reviewed fact matching is a helper for later lead/scoring integration. Visual scoring cannot be enabled with an unreviewed calibration string. Currentness comparisons are available, but affected-campaign/result counts remain zero until those modules exist. Semantic hashes cover target text, desired needs and preferences, so weights alone do not invalidate those inputs. Verified 126 tests, live routes and exact preservation of existing agency/service records after upgrading the real database.

The test runner uses isolated project-local cache/temporary folders for each run. The downloaded-model ignore rule is rooted at `/models/`; it must not hide ORM source files, now located in `backend/app/modules/<feature>/models/`. Those source files were absent from the first Git commit because of the broader old ignore rule and were required for the subsequent module 03 commit. No commit or push was performed automatically for that correction.

## Module 02 — Agency and services

Implemented singleton profile and service CRUD/deactivation with schema version 2. Contact fields are email, phone and HTTP/HTTPS website; PATCH replaces the contact object. Service lists default to active records, with include_inactive and pagination. GET by service ID is added to expose the current ETag conveniently. Mutations use short IMMEDIATE transactions and revision-checked updates; identical edits retain their revision. Activities record changed field names/revisions rather than full descriptions or contact details. Migration 002 rebuilds both activities and their dependent cleanup table transactionally to preserve existing links while adding the agency FK. Future draft freshness compares captured service revisions; no draft tables are assumed before module 13.

## Phase 1 — 7 October 2026

- **Implemented:** FastAPI API shell, SQLAlchemy/SQLite, explicit short transactions, WAL and per-connection foreign keys, numbered migration ledger, safe errors and storage helpers. The API acquires/releases database resources through [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/).
- **Tested environment:** Windows 11, Python 3.14.8, approximately 247 GB free on E: when measured. These are foundation observations, not model performance measurements.
- **Dependencies:** exact versions are in `backend/requirements.lock.txt`. FastAPI is constrained below 0.130 for the tested Starlette/HTTPX TestClient stack. The first resolution selected FastAPI 0.142.2/Starlette 1.7.0, whose TestClient deprecates HTTPX; the tested selection is FastAPI 0.129.2/Starlette 0.52.1. Only Starlette's known AnyIO BlockingPortal alias deprecation is filtered in pytest; other warnings remain errors.
- **Database:** foreign keys are enabled for every connection, and BEGIN is explicit so failed DDL rolls back. See [SQLAlchemy's SQLite documentation](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html). Migration 001 contains frozen DDL, so future ORM changes do not silently change old migrations.
- **Configuration:** Pydantic Settings loads `backend/.env` and environment variables; invalid inputs are hidden in validation error text. See [Pydantic Settings documentation](https://pydantic.dev/docs/validation/latest/concepts/pydantic_settings/).
- **Scope:** worker state, maintenance flag and cleanup helpers exist; there is no job worker, business CRUD, coordinated backup/restore or AI processing yet. Activity domain foreign keys arrive when agency/campaign/lead tables exist.
- **Deferred compatibility:** use installed Python for phase 1; check Torch/OpenCV/Playwright and model memory in their own modules. No model or optional package was downloaded.
- **Swagger:** default CDN assets are retained for this backend shell. Health/tests work offline after dependencies are installed; the saved-evidence offline UI remains required later.
- **Git:** executable unavailable in the terminal. Local initialization and first push have not occurred; install/configure Git before starting source history.

## Phase 6: persistent processing

Use one separate worker and SQLite, without a queue service. The OS process lock controls ownership; heartbeat is only a readiness signal, never permission to steal work. After acquiring a released lock, a new worker marks unfinished running jobs JOB_INTERRUPTED. User retry creates a new immutable run from current inputs; exact idempotency replays retain the original run. Per-stage output and activity commit together in short transactions. Cancellation keeps finished stage outputs. Deadlines are cooperative and future handlers must bound network/model calls. Unbuilt production handlers fail STAGE_NOT_IMPLEMENTED; test fakes never supply production results. Saved modes and runtime resource pins integrate as their modules arrive.

## Phase 7: saved evidence first

Follow the agreed sequence: saved evidence unlocks NLP/CV/scoring; live fetch/proxy/browser safety is completed afterward. Add only Pillow 12.3.0 to the existing locked dependency set. A durable manifest reserves opaque artifact keys before file writes, and one-hour expiry cleans abandoned reservations. Validate before writing; preserve originals; derive an oriented bounded thumbnail. Atomic job attachment consumes a lead-scoped hashed token after replay checks. Acquisition evidence, stage output and activity commit together. User reviews retain provenance and invalidate currentness; retry pins those reviews when reusing saved evidence. Owned download routes read bounded bytes and verify their hash. Lead deletion queues file cleanup in the same transaction and returns 202 until that cleanup is processed. Saved evidence never implies a live visit or verified company claims.

## Phase 8: local source-linked NLP

Use the user's existing qwen2.5:3b with its installed digest and verified research license; do not download the earlier 1.5b candidate. A two-fixture trial demonstrates integration, citations and unknown employee counts, while broader quality/peak-RAM acceptance remains pending. API submission reads worker-refreshed model metadata and never waits for inference. Local HTTP ignores environment proxies and redirects, bounds response bytes, and supports cooperative cancellation. Exact source quote checks are provenance checks, not proof of entailment; all interpretations require review. Keep user corrections separate and authoritative. Cache keys bind exact text selection, evidence/review/manual revisions, services, digest, prompt/schema and parameters. Immutable analyses commit with stage output/activity. No model output changes pipeline or lead fields. Failed raw output stays private for 24 hours.

## Phase 9: deterministic saved-image measurements

Add pinned headless OpenCV and NumPy. Preserve the original image, orient and composite a separate working copy, and bound it to 683 by 2,048 pixels. Use fixed Canny, histogram and tile definitions with library versions in each snapshot and result. Store immutable measurements transactionally with their stage/activity record. Cache only exact image/configuration/review inputs, and verify bytes even on reuse. Review changes invalidate history and are checked again before commit. Missing/rejected images have null metrics. Keep visual weight zero and omit uncalibrated heuristics; six synthetic numerical fixtures are not human website calibration.

## Phase 10: local CPU text embeddings

Use the planned MiniLM model with its official, checksum-pinned ONNX export and native tokenizer. CPU ONNX inference avoids adding Torch for this module; dependencies remain locked. API requests read worker-verified readiness without model loading. Explicit setup is the only downloader. Both sides share revision/config, attention-mask mean pooling, L2 normalization and explicit 256-token selection. Cache by agency/purpose/input/model space; store bounded float32 bytes, never pickle. Preserve source/review provenance and immutable results; lead cache references allow safe deletion after failures and shared reuse. Keep semantic similarity separate from final scoring and hard exclusions, which arrive in module 11.

## Phase 11: explained scoring and reviewer history

Implement weighted-fit-v1 with saved ICP thresholds and exact E/A/N arithmetic. Only entered/reviewed structured fields and valid semantic results supply values. Missing facts reduce coverage; mismatches provide known zeros. Exclusions are independent and visual weight remains zero. Save immutable score/component rows with stage/activity in one transaction. Read currentness dynamically, mark superseded historical scores, suppress stale recommendations and filter computed priority before pagination. Append reviewer decisions and clear records beside the computed result, binding them to the current inputs; qualification records do not enact transitions. Extend terminal-job retry to completed analyses so users can recompute without uploading the same evidence again. No new dependency is added in this module.

## Live evidence milestone

Finish module 07 after scoring, adding Playwright and its locked dependency only. Reuse installed Chrome after the optional Chromium download timed out; record actual browser versions and rerun egress checks after updates. Use stdlib exact-IP HTTP/TLS and a capture-specific validating proxy instead of trusting a DNS precheck followed by hostname connection. Disable browser direct-network fallback, workers, WebSockets, service workers, QUIC and non-proxied WebRTC. Reject compressed text responses when a server ignores identity encoding. Keep robots denial, time/size limits and partial results explicit. Reserve live files before writes; schema 012 extends existing evidence without relabelling cached sources. No discovery/login/bypass feature is added.

## NLP citation and truncation repair

Keep the public BusinessOutput contract and strict source validation. Use a tighter generation-only schema with real excerpt choices and controlled observation IDs to prevent joined invented quotes and arbitrary headings as references. Preserve the v1 prompt and use versioned v2 for new runs/cache identities. Route incomplete model answers through the existing two-call repair budget, retain rejected output privately and prevent a transport retry after repair from creating a third call. Retest the actual failed Arbisoft evidence and both synthetic local-model fixtures in isolated databases. Earlier runs remain immutable; recompute rather than rewriting history.
